# 07. Безопасность и соответствие

## 1. Модель угроз

| Угроза | Вектор | Мера |
|---|---|---|
| Несанкционированный доступ к API | Кража cookie/токена, перебор пароля | HttpOnly + SameSite=Strict, TTL 2 ч, `tokenVersion`, lockout, rate limit |
| Подмена/повышение роли | Правка JWT, прямой вызов админского маршрута | HS256 + подпись, `isActive`/`role` из БД, RBAC на двух уровнях (proxy + handler) |
| IDOR | Подстановка чужого `caseId`/`patientId` | `requireCaseAccess` / `requirePatientAccess`, гранты, проверка владельца |
| Утечка ПДн в ИИ/облако | Отправка сырого текста в модель/поиск | Де-идентификация до LLM, `query-sanitizer`, локальный LLM |
| Утечка файлов | Прямой доступ к `/public/uploads` | `private-storage`, шифрование at-rest, выдача через API |
| Подмена клинических данных | Прямая правка БД, обход аудита | Hash-chain аудит, append-only, verify endpoint |
| Кража E2EE-ключей | Дамп памяти/диска браузера | Ключи только в памяти, Argon2id, auto-lock, X25519-обёртки |
| SSRF через настройки ИИ | `URL=http://169.254.169.254/...` | Allowlist хостов, откат на localhost |
| Загрузка вредоносного файла | SVG/HTML с активным содержимым | Allowlist расширений/MIME + magic bytes, SVG запрещён |
| XSS через вывод модели | HTML в заключении | Вывод рендерится как текст (`stripMarkdown`), без `dangerouslySetInnerHTML` |
| DoS перебором | Массовые логины/запросы | Rate limit 20/мин (auth) и 300/мин (API), lockout 5/15 мин |
| Компрометация секретов | `.env` в репозитории/демо | `.gitignore`, fail-fast, чёрный список утёкших значений, ротация |

## 2. Аутентификация

- **JWT HS256**: `iss=sppvr-cdss`, `aud=sppvr-cdss-api`, TTL **2 часа**, `jti`, `tokenVersion`.
- **Cookie `token`**: `HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS, `Path=/`.
  Клиент не хранит токен в `localStorage` (`setAuthToken` оставлен для совместимости и
  вычищает легаси-ключ).
- **Скользящее продление** в proxy: при остатке < 1 ч токен перевыпускается.
- **Мгновенный отзыв**: `Doctor.isActive=false` или инкремент `tokenVersion` → все токены
  недействительны. Проверка кэшируется 30 с (`getAccountCheck`).
- **Пароли**: bcrypt cost 12; политика ≥ 10 символов, буква + цифра, ≤ 72 байт (ограничение
  bcrypt), запрет тривиальных; смена — через `?action=set-password`.
- **Lockout**: 5 неудачных попыток → блокировка на 15 минут; попытки и блокировки пишутся
  в аудит. Ответ на неверный код и неверный пароль одинаковый (нет энумерации).
- **Инициализация**: `POST /api/auth/init` принимает запросы только с localhost; одноразовый
  пароль администратора (18 символов) показывается один раз, хранится только bcrypt-хеш.

## 3. Авторизация

| Механизм | Модуль | Правило |
|---|---|---|
| `requireAuth` | `src/lib/auth.ts` | Валидный JWT + активный аккаунт + совпадение `tokenVersion` |
| `requireAdmin` | `src/lib/auth.ts` | `role === "admin"` |
| `requireCaseAccess` | `src/lib/case-access.ts` | Владелец кейса, активный `CaseShare` или админ |
| `requirePatientAccess` | `src/lib/patient-access.ts` | Владелец карты, активный `PatientAccessGrant` (с учётом `expiresAt`) или админ |
| Proxy allowlist | `src/proxy.ts` | Публичные маршруты, админские пути, rate limit |
| RBAC в handler | каждый route | Defense-in-depth: даже если proxy пропустил, handler проверит |

Админские операции (proxy + handler): создание/изменение врачей, seed, шаблоны (мутации),
`/api/encryption`, `/api/logs`, `/api/backup`, `/api/audit*`, `/api/analytics`.

Публичные маршруты: `/api/auth*` (кроме `auth/key`), `/api/health`, `/api/network/status`,
`GET /api/doctors`, `GET /api/recommendations`, `GET /api/icd10`, `GET /api/ddi`,
`GET /api/pathways`, `GET /api/templates`.

## 4. E2EE карт пациентов

### 4.1 Схема ключей

```
парольная фраза врача
   └─ Argon2id (128 MiB, 3 итер., 4 потока; пресеты fast/high/maximum)
        └─ KEK ──► разворачивает wrappedWdek (ключ врача)
             └─ DEK врача (мастер-ключ)
                  └─ заворачивает PDEK пациента (wrappedPdek)
                       └─ PDEK шифрует поля карты (enc:v1:…)
```

- Для передачи карты коллеге создаётся `X25519`-пара; PDEK пере-оборачивается под публичный
  ключ получателя (`PatientAccessGrant.wrappedPdek`). Сервер не может развернуть ни один ключ.
- `checkBlob` позволяет проверить правильность пароля без расшифровки данных.
- Ключи живут **только в памяти вкладки** (`useE2EESession`), авто-блокировка по бездействию.
- Шифрование полей — каскад `AES-256-GCM-SIV` + `ChaCha20-Poly1305` (`src/lib/crypto`),
  контейнерный формат с версией, KDF-параметрами и nonce-трекером (защита от повторного nonce).

### 4.2 Что видит сервер

| Данные | Сервер |
|---|---|
| ФИО, телефон, e-mail, адрес, СНИЛС, полис, ДМС, национальность, профессия, заметки, дата рождения | Только шифротекст |
| `patientToken`, пол, год рождения, группа крови, аллергии, проблемы, витальные, лаборатория | Открыто (псевдонимизировано) |
| Документы кейса | Шифротекст на диске; `deidContent` — открытый де-идентифицированный текст |
| Ключи | Никогда (только публичные обёртки) |

### 4.3 Ограничения E2EE

- Восстановление пароля невозможно: потеря парольной фразы = потеря доступа к ПДн.
- Администратор не может прочитать карту без гранта.
- Поиск по ФИО на сервере невозможен (поиск идёт по токену/клиническим полям).

## 5. Шифрование файлов at-rest

`src/lib/encryption.ts`:

- Ключ выводится из `ENCRYPTION_KEY` через **scrypt** с усиленными параметрами (выше OWASP-минимума).
- Шифр — **AES-256-GCM**, случайный IV (16 байт), тег аутентификации.
- Файлы лежат в `private-storage/uploads/*.enc` (+ `.meta`), не отдаются статикой.
- Выдача — только через API с проверкой доступа и расшифровкой в поток.
- `scripts/rotate-encryption-key.ts` — перешифрование при ротации ключа.

## 6. Де-идентификация

| Слой | Модуль | Что удаляет/заменяет |
|---|---|---|
| Regex/эвристики | `deidentify.ts` | ФИО, СНИЛС, полис, паспорт, ИНН, телефон, e-mail, адрес, даты |
| Локальный NER | `ner-deidentify.ts` | Сущности по словарю (имена, организации, локации) |
| Санитайзер запросов | `query-sanitizer.ts` | PHI и точные идентификаторы перед внешним поиском |

- В LLM уходит только `deidContent`.
- Внешние поисковые запросы строятся из диагнозов/терминов, а не из текста пациента.
- Проверки `containsPHI` / `textContainsPHI` используются в тестах и при загрузке.

## 7. Аудит и целостность

- Каждая запись `AuditLog`: `hash = SHA-256(action|details|caseId|doctorId|ip|userAgent|createdAt|prevHash)`.
- Запись сериализована promise-очередью (`appendAudit`) — конкурентные вставки не рвут цепочку.
- `GET /api/audit/verify` (admin) проходит цепочку и сообщает о расхождении.
- Журнал append-only: кода обновления/удаления нет.
- Экспорт — `GET /api/audit/export`.
- В аудите нет открытых ПДн — только идентификаторы и метаданные.

## 8. Сетевые и браузерные меры

`next.config.ts` (все ответы):

| Заголовок | Значение |
|---|---|
| `Content-Security-Policy` | `default-src 'self'`; `script-src 'self' 'unsafe-inline'` (в dev + `'unsafe-eval'`); `object-src 'none'`; `frame-ancestors 'none'` |
| `X-Frame-Options` | `DENY` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | camera/mic/geo/payment/usb/bluetooth/gyroscope = () |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains` |
| `poweredByHeader` | выключен |

- **Rate limit**: 20/мин на `/api/auth*`, 300/мин на остальное, окно 1 мин, ключ — `x-real-ip`
  (Caddy) или первый `x-forwarded-for`.
- **SSRF**: ИИ-URL только localhost + allowlist; внешние вызовы — через `safeFetch` с
  circuit breaker.
- **Загрузки**: allowlist расширений/MIME, magic-bytes (PDF `%PDF-`, OOXML `PK\x03\x04`),
  лимит 25 МБ, SVG запрещён, файлы не в `public/`.

## 9. Секреты и инцидент 2025-09-07

- `JWT_SECRET` и `ENCRYPTION_KEY` — ≥ 64 символов; приложение **не стартует** при слабом/
  отсутствующем секрете (`fail-fast`), `/api/*` возвращает `503` (`fail-closed`).
- Чёрный список утёкших значений: восстановление старого `.env` невозможно.
- Пароль администратора при инициализации не хардкодится и не хранится в открытом виде.
- `.env` в `.gitignore`; `scripts/ensure-env.ts` дописывает только отсутствующие значения.
- Ротация: JWT — смена секрета (все сессии инвалидируются); файлы — `rotate-encryption-key.ts`.

## 10. Соответствие требованиям

| Требование | Реализация |
|---|---|
| ФЗ-152 ст. 18 ч. 3 — защита ПДн от неправомерного доступа | RBAC, E2EE, шифрование файлов, TLS, CSP, rate limit |
| ФЗ-152 ст. 9 — согласие субъекта | `Consent` (типы, срок, отзыв), гейт `ai_analysis` перед анализом |
| ФЗ-152 ст. 5 — минимизация | Де-идентификация, передача модели только необходимого |
| HIPAA §164.312(a)(1) — access control | JWT, роли, case/patient access, lockout |
| HIPAA §164.312(a)(2)(iv) — encryption | E2EE карт, AES-256-GCM файлов, Argon2id |
| HIPAA §164.312(b) — audit controls | Hash-chain журнал, verify, экспорт |
| HIPAA §164.312(c)(1) — integrity | Append-only аудит, снапшоты версий анализа |
| HIPAA §164.312(e)(1) — transmission security | HTTPS/Caddy, HSTS, SameSite cookie |

> Документ описывает технические меры, а не юридическое заключение. Соответствие конкретному
> регулятору подтверждается организационными процедурами (DPIA, приказ о допуске, обучение).

## 11. Остаточные риски

1. **Один узел**: компрометация сервера = доступ к метаданным и шифротексту; E2EE защищает
   содержимое карт, но не факт наличия пациента.
2. **SQLite без шифрования файла БД**: рекомендуется BitLocker/LUKS на диске.
3. **Память браузера**: XSS на странице теоретически может добраться до ключей; CSP и
   отсутствие сторонних скриптов снижают риск, но не исключают.
4. **Локальная модель**: промпт-инъекция через содержимое документа возможна; вывод не
   исполняется, но может содержать ложные утверждения — обязательна проверка врачом.
5. **Резервные копии**: JSON-бэкап содержит шифротекст ПДн; хранить его нужно так же
   строго, как БД.
6. **Rate limit in-memory**: при нескольких экземплярах лимиты не общие.
