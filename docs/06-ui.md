# 06. Интерфейс

## 1. Оболочка приложения

`src/app/page.tsx` — единственная страница (SPA). Внутри:

```
QueryClientProvider → E2EEProvider → AuthGate → AppShell → MainContent
```

- `MainContent` переключает «вьюхи» по `useAppStore().view`; каждая грузится лениво
  (`next/dynamic`) — начальный бандл не тянет весь интерфейс.
- `AppShell` — верхняя панель, боковая навигация (на мобильных — нижняя), переключатель
  темы, статус системы, уведомления, профиль врача, командная палитра (`Ctrl/⌘+K`).
- `AuthGate` — экран входа/инициализации, если нет сессии.

| Пункт меню | `View` | Экран |
|---|---|---|
| Рабочий стол | `dashboard` | KPI, последние кейсы, здоровье системы |
| Карта пациента | `medical-record` | ЭМК, 11 вкладок |
| Калькуляторы | `calculators` | Клинические шкалы и калькуляторы |
| Аналитика | `analytics` | Агрегированные метрики (admin) |
| Аудит | `audit` | Журнал действий (admin) |
| База знаний | `knowledge` | Поиск, документы, КР |
| Администрирование | `admin` | Врачи, ключи, шифрование, логи (admin) |
| О системе | `about` | Версия, соответствие требованиям |

Роль `doctor` не видит «Аналитику», «Аудит» и «Администрирование».

## 2. Карта пациента (`medical-record`)

Вкладки: **Обзор · Хронология · Визиты · Витальные · Препараты · Лаборатория ·
Обследования · Проблемы · Прививки · Планы · ИИ-Анализ**.

- «Обзор» — демография, аллергии, активные проблемы, последние показатели.
- «Хронология» — единая лента событий (визиты, анализы, обследования).
- «Обследования» — статусы (`ordered`→`scheduled`→`in_progress`→`completed`), просроченные,
  привязка к КР (`clinrecCodeVersion`).
- «ИИ-Анализ» — `PatientAnalysisTab` + `InlineAiPanel` (быстрый разбор без кейса).
- Прямые идентификаторы (ФИО, СНИЛС, телефон…) отображаются только после разблокировки
  E2EE-хранилища.

## 3. Рабочее место кейса (`case-workspace`)

Шапка: код кейса, статус, подсказка диагноза, год рождения, пол, врач. Ниже —
`PatientSummaryCard` (риск, диагноз, ключевые данные).

Вкладки кейса:

| Вкладка | Компонент | Назначение |
|---|---|---|
| Документы | `UploadZone`, `DocumentViewer` | Загрузка, просмотр, де-идентифицированный текст |
| Анализ | `AnalysisPanel` | Результат ИИ (см. §4) |
| Терапия | `TherapyRecommendationsPanel` | Терапевтические опции (устаревший контур; новые — в `structured`) |
| Контроль | `ControlPanel` | Веса факторов, комментарии врача, ручная правка заключения |
| Отчёты | `ReportPanel` | Генерация PDF, статусы, подписи |
| Доступ | `CaseSharePanel` | Передача кейса коллеге (read/comment) |
| Согласия | `ConsentManager` | Согласия ФЗ-152, включая `ai_analysis` |

Без согласия `ai_analysis` запуск анализа заблокирован на клиенте и сервере.

## 4. Панель анализа — 8 вкладок

`src/components/shared/analysis-panel.tsx` (оболочка) + `workup-tracker.tsx` +
`analysis-audit-panel.tsx`.

### 4.1 Шапка

- Название, версия анализа, бейдж самопроверки (тултип со списком исправлений).
- Кнопки «История» (сравнение версий) и «Повторить анализ» (с прогрессом).
- **KPI-полоса** (4 кликабельные плитки): рабочий диагноз и вероятность · выполнено/всего
  в плане + срочные · опции терапии и разблокировано · балл проверки и число критичных.

### 4.2 Вкладки

| Вкладка | Что внутри |
|---|---|
| **Обзор** | Ведущая гипотеза (аргументы за/против, красные флаги, КР), «Срочно — выполнить первыми», проверка рекомендаций (топ-3), безопасность (аллергии/почки/терапия), уверенность модели |
| **Гипотезы** | Аккордеон 3–5 гипотез: вероятность, МКБ-10, КР, аргументы, обследование, красные флаги, источники, кнопка «Подтвердить диагноз» (диалог с обоснованием) |
| **Обследование** | Трекер (см. §4.3) |
| **Терапия** | Карточки по гипотезам; заблокированы до подтверждения; доза, обоснование, доказательность, источник, предупреждения |
| **Контроль** | Маркеры мониторинга: цель, частота, зачем |
| **Источники** | DDI-алерты, МКБ-10, генетические варианты, RAG-рекомендации, клинические пути, изображения, цитаты (XAI) |
| **Текст ИИ** | Полное заключение + разделы, копирование в буфер |
| **Проверка** | Балл 0–100, замечания по severity с действиями, автоматические исправления структуры, отчёт самопроверки |

### 4.3 Трекер обследований

- Прогресс-бар, счётчики (срочные, назначено, результаты).
- Поиск, фильтры «Все / Не закрыто / Выполнено / Есть результат», переключатель «Срочные».
- Строка: статус (`select`), название, приоритет, срок, привязка к гипотезам, «Норма/пороги».
- Раскрытие: ожидаемый результат, подготовка, «подтверждает/исключает, если», руководство
  по интерпретации, ввод результата и комментария.
- Ввод результата автоматически переводит пункт в «Результат получен» (если он не был закрыт)
  и показывает арифметическую сверку с референсом.
- «Скопировать план» — текст для карты/направления.
- Сохранение — серверное (`PATCH analysis/control`), с оптимистичным обновлением и откатом
  при ошибке; каждое изменение попадает в аудит.

### 4.4 Поведение и доступность

- Подтверждение диагноза optimistic: UI реагирует сразу, при ошибке — откат и toast.
- Кнопки и `select` имеют `aria-label`; кликабельные KPI — `<button>`; фокус видим.
- Интерактивные элементы ≥ 28–44 px; таблицы не используются, чтобы работало на планшете.
- Тёмная тема поддерживается через CSS-переменные (`next-themes`).

## 5. Состояние и данные

| Хранилище | Что | Ключи/поля |
|---|---|---|
| `useAppStore` (zustand + persist) | Навигация, выбранный кейс/пациент, профиль, локаль, сайдбар | `view`, `selectedCaseId`, `selectedPatientId`, `currentDoctor`, `locale` |
| TanStack Query | Серверные данные | `["case", id]`, `["analysis", id]`, `["consents", id]`, `["patients"]`… |
| E2EE session (zustand, memory only) | DEK/PDEK, статус разблокировки | `useE2EESession` |
| localStorage | Только `sppvr-store` (без JWT), легаси-ключ вычищается | `purgeLegacyToken()` |

Правила инвалидации: изменение анализа/трекера/подтверждения → инвалидировать
`["case", id]` **и** `["analysis", id]`; изменение карты пациента → `["patient", id]` и список.

## 6. E2EE в интерфейсе

1. После входа — проверка наличия key material; при отсутствии предлагается создать
   (парольная фраза + Argon2id в Web Worker).
2. Разблокировка — диалог пароля; ключи живут только в памяти вкладки.
3. Автоблокировка по бездействию (`startAutoLock`), ручная блокировка в меню профиля.
4. Пока хранилище заблокировано, карты пациентов показывают заглушки вместо ПДн.
5. Передача карты коллеге — `PatientShareDialog` (пере-оборачивание PDEK под его ключ).

## 7. Дизайн-система

- **shadcn/ui** (Radix) + `class-variance-authority` + `tailwind-merge`; 48 компонентов
  в `src/components/ui` — не форкать без необходимости.
- Токены — `src/app/globals.css` (oklch): `--primary` (медицинский teal), `--card`, `--border`,
  `--destructive`; классы `bg-medical-gradient`, `bg-medical-gradient-soft`.
- Плотность: карточки `gap-3 py-3`, заголовки `px-3 pb-1.5` — сознательно компактнее
  дефолта shadcn (клинический экран должен показывать больше без скролла).
- Иконки — `lucide-react`; статусы кодируются цветом **и** текстом (не только цветом).
- Анимации — `framer-motion`, `tailwindcss-animate`; отключаются системным
  `prefers-reduced-motion` средствами Tailwind.

## 8. Локализация

- `src/lib/i18n.ts`: `Locale = "ru" | "en"`, словари `src/lib/translations/{ru,en}.ts`,
  функция `t(key, locale)`.
- Русский — основной; английский покрывает навигацию и общие подписи. Клинические тексты
  (заключения ИИ) всегда русские.
- Переключатель языка — в шапке; выбор сохраняется в zustand.

## 9. Как добавить экран или вкладку

1. Создайте компонент в `src/components/views/` (или `shared/` для панели).
2. Добавьте `View` в `src/lib/store.ts` и `switch` в `src/app/page.tsx` (+ `dynamic`).
3. Пункт меню — `getNavItems` в `app-shell.tsx` (при необходимости `adminOnly`).
4. Для новой вкладки панели анализа: `PanelTab`, `TAB_LABELS`, `TabsTrigger`, `TabsContent`;
   счётчик — из соответствующего массива `structured`.
5. Проверьте: клавиатурная навигация, `aria-label`, тёмная тема, мобильная ширина 360 px.

## 10. Известные UX-ограничения

- Горизонтальная лента вкладок панели анализа на узких экранах прокручивается; активная
  вкладка может оказаться частично скрытой.
- Длинные названия гипотез обрезаются (`truncate`) — полный текст в `title` и в карточке.
- Нет офлайн-режима редактирования: при потере сети запросы падают, статус показывается
  в «Здоровье системы».
- Демо-кейсы, созданные до v5.2, не имеют `structured` — панель показывает предупреждение
  и текст заключения; нужен повторный анализ.
