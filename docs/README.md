# СППВР — техническая документация

> Система поддержки принятия врачебных решений (Clinical Decision Support System).
> Локальное (on-premise) развёртывание: данные пациентов не покидают контур,
> ИИ-инференс — на собственном OpenAI-совместимом сервере.

| Параметр | Значение |
|---|---|
| Версия приложения | `0.2.1` (`package.json`) |
| Версия ИИ-конвейера | v5.2 (диф. диагноз → обследование → терапия + трекер + аудит) |
| Стек | Next.js 16 (App Router), React 19, TypeScript 5, Tailwind CSS 4, Prisma 6 + SQLite |
| Объём кодовой базы | 226 TS/TSX-файлов, ≈67 000 строк (без тестов) |
| API | 72 route handler'а, 1 edge-proxy |
| Модель данных | 31 модель Prisma, JSON-агрегаты в текстовых колонках |
| Тесты | Vitest, 63 теста в 5 файлах |
| Лицензия | приватный проект; обращение с ПДн — по внутренним политикам организации |

## 1. Назначение

СППВР сопровождает клинический случай от загрузки документов до подписанного отчёта:

1. **Документы** — выписки, генетические отчёты (VCF/CSV), изображения (DICOM/PNG/JPEG), PDF/DOCX.
2. **Де-идентификация** — PHI вырезается локально до любого обращения к модели.
3. **ИИ-разбор** — дифференциальный диагноз (3–5 гипотез с аргументами), план дообследования
   с референсами и критериями, терапия только после подтверждения диагноза, мониторинг.
4. **Проверка** — детерминированный аудит набора рекомендаций (26 правил) и отчёт самопроверки модели.
5. **Работа врача** — подтверждение гипотезы, трекер выполнения обследований, DDI, отчёты, подписи, аудит.

Ключевой принцип: **ИИ предлагает — врач подтверждает**. Терапия заблокирована до подтверждения
диагноза, все действия врача фиксируются в журнале аудита.

## 2. Быстрый старт

```bash
bun install                      # или npm install
cp .env.example .env             # секреты допишутся при первом запуске
bun run db:push                  # создать/обновить SQLite (db/custom.db)
bun run dev                      # http://localhost:3000
```

Первый вход: инициализация системы (`POST /api/auth/init` или кнопка в интерфейсе) → одноразовый
пароль администратора выдаётся один раз и требует смены при первом входе.

Подробно: [02-installation.md](02-installation.md).

## 4. Структура репозитория

```
prisma/schema.prisma        схема БД (31 модель), миграции
db/custom.db                SQLite-база (создаётся локально)
private-storage/uploads/    зашифрованные файлы (не отдаются как статика)
scripts/                    ensure-env.ts, rotate-encryption-key.ts
src/proxy.ts                edge-proxy: публичные маршруты, RBAC, rate limit
src/app/api/                route handlers (72)
src/app/page.tsx            единственная страница (SPA-оболочка)
src/components/views/       экраны приложения
src/components/shared/      панели (анализ, ЭМК, отчёты, DDI, согласия…)
src/components/ui/          shadcn/ui (48 компонентов, не модифицировать без нужды)
src/lib/                    доменное ядро: auth, AI, RAG, crypto, e2ee, audit, validation
src/lib/seed/               демо-данные и справочники (МКБ-10, DDI, КР, пути)
```

## 5. Соглашения

- **Язык интерфейса и клинического текста** — русский; идентификаторы кода — английский.
- **Деньги пациентов не касаются**: система не содержит биллинга и не передаёт ПДн в облако.
- **Комментарии в коде** — на русском, объясняют *почему*, а не *что*; сохраняйте этот стиль.
- **JSON-колонки** (`AnalysisResult.*`, `Case.icd10Codes`, `Patient.allergies` и др.) описаны в
  [03-data-model.md](03-data-model.md); менять их формат — только с миграцией чтения.
- **Новые API-маршруты** обязаны: валидировать вход zod-схемой, проверять доступ
  (`requireAuth` / `requireCaseAccess` / `requirePatientAccess` / `requireAdmin`) и писать аудит
  для действий, изменяющих клинические данные.

## 6. Известные ограничения

- **Один экземпляр**: rate limit, очередь аудита и кэш здоровья LLM — in-memory. Горизонтальное
  масштабирование потребует внешнего хранилища (Redis) и блокировок.
- **SQLite**: один писатель; при нескольких одновременно работающих врачах возможны блокировки
  записи. Для отделения на 5–10 человек при локальном развёртывании это приемлемо.
- **Локальная модель** ограничена контекстом и качеством: промпт и детерминированные проверки
  снижают, но не устраняют риск ошибочных формулировок. Финальное решение — за врачом.
- **Публичная регистрация закрыта** по умолчанию (`REGISTRATION_OPEN=false`); врачей создаёт админ.
- **Edge-proxy** покрывает только `/api/*`; страницы защищены клиентским `AuthGate` и серверными
  проверками в маршрутах. Не размещайте сервис в интернете без TLS-терминатора.
- Актуальный список дефектов и незакрытых задач — в [08-testing.md](08-testing.md).
