# 08. Тестирование и качество

## 1. Инструменты

| Инструмент | Команда | Что проверяет |
|---|---|---|
| TypeScript | `npm run typecheck` | Строгая типизация (`tsc --noEmit`, `strict: true`) |
| ESLint | `npm run lint` | Next.js + TypeScript правила, React hooks/compiler |
| Vitest | `npm test` | Юнит-тесты доменного ядра (node-окружение) |
| Next build | `npx next build` | Сборка, RSC/клиентские границы, статические маршруты |

Конфигурация Vitest — `vitest.config.ts`: `environment: node`, `include: src/**/*.test.ts`,
алиас `@ → src`. UI-тестов и E2E в репозитории нет — это осознанное ограничение текущей версии.

## 3. Что не покрыто (зона ручной проверки)

- HTTP-маршруты (нет интеграционных тестов с БД и сессией).
- UI и доступность (нет Playwright/RTL).
- Реальная генерация LLM (нельзя детерминированно проверить качество текста).
- E2EE end-to-end в браузере (крипто-примитивы покрыты, сценарий разблокировки — нет).
- Внешние источники (Минздрав, PubMed, DDI): зависят от сети.

Для этих зон используйте чек-лист §5.

## 4. Известные дефекты и ограничения

| Дефект | Влияние | Статус |
|---|---|---|
| `src/components/auth/login-dialog.tsx:66` — ESLint `Cannot access variable before it is declared` (`runInit`) | Только lint, сборка проходит | Существовал до v5.2; требует рефакторинга порядка объявлений |

| Старые анализы без `structured` | Новый экран показывает предупреждение | Нужен повторный анализ |

## 5. Чек-лист ручной проверки

### 5.1 Установка и вход

- [ ] `GET /api/health` → `ok`, `db`, `ai`, `rag`, `ddi`, `icd10`.
- [ ] Инициализация выдаёт одноразовый пароль; повторная инициализация запрещена.
- [ ] Вход неверным паролем 5 раз → блокировка на 15 минут, запись в аудите.
- [ ] Смена пароля при первом входе; после смены старые сессии недействительны.

### 5.2 Кейс и документы

- [ ] Создание кейса, загрузка PDF/DOCX/VCF/изображения.
- [ ] Файл > 25 МБ → `413`; `.svg`/`.exe` → отказ.
- [ ] `deidContent` не содержит ФИО/СНИЛС/телефона.
- [ ] Удаление документа фиксируется в аудите.

### 5.3 Анализ

- [ ] Без согласия `ai_analysis` → `403 CONSENT_MISSING`.
- [ ] С согласием → анализ завершается, версия = 1.
- [ ] В «Обзоре» видны гипотезы, срочные тесты, балл проверки.
- [ ] «Проверка»: замечания соответствуют данным (нет ложных critical на корректном наборе).
- [ ] Подтверждение диагноза разблокирует терапию и пишется в аудит.
- [ ] Трекер: смена статуса сохраняется после перезагрузки страницы (сервер!).
- [ ] Ввод результата показывает сверку с нормой.
- [ ] Повторный анализ: версия +1, `confirmedDx` и трекер перенесены.
- [ ] «История версий» показывает снапшот.

### 5.4 E2EE

- [ ] Первый вход: создание ключей (Argon2id), карта открывается.
- [ ] Перезагрузка → требуется разблокировка, ПДн скрыты.
- [ ] Передача карты коллеге → получатель видит данные, третий врач — нет.
- [ ] Блокировка по бездействию срабатывает.

### 5.5 Отчёты и аудит

- [ ] Генерация PDF, водяной знак, кириллица.
- [ ] Подпись `approval` → статус `signed`, повторная подпись → `409`.
- [ ] `GET /api/audit/verify` → цепочка валидна.
- [ ] Экспорт аудита (admin) содержит действия врача, но не ПДн.

```bash
npm test               # 63+ теста, 0 падений
npm run lint           # 0 ошибок (warnings допустимы)

```

1. Проверить `prisma/migrations` (нет неприменённых миграций).
2. Сделать бэкап БД и `private-storage`.
3. Проверить, что `.env` не в репозитории и секреты ≥ 64 символов.
4. Пройти §5.1–5.5 на стенде.
5. Обновить документацию (`docs/`) при изменении поведения.
6. Зафиксировать версию в `package.json` и в шапке `docs/README.md`.

## 7. Как добавить тест

1. Файл рядом с модулем: `src/lib/<module>.test.ts` (Vitest подхватит автоматически).
2. Импортируйте чистые функции напрямую; не тяните `db`, `next/server` и env-зависимые модули.
3. Для правил аудита добавляйте по одному кейсу на правило (id в `findings.map(f => f.id)`).
4. Для нормализации проверяйте и результат, и `fixes` (это то, что увидит врач).
5. Тест должен падать при регрессии, а не «подстраиваться» под реализацию.

## 8. Метрики качества

| Метрика | Где смотреть | Ориентир |
|---|---|---|
| Балл проверки рекомендаций | `AuditLog.details.auditScore`, UI «Проверка» | ≥ 85 на большинстве кейсов |
| Критичные замечания | `auditCritical` в аудите | 0–1 |
| Доля анализов без `structured` | `AnalysisResult.structured = "{}"` | → 0 после повторного анализа |
| Время анализа | лог `analysis` (`elapsedMs`) | зависит от железа |
| Ошибки LLM | `SystemLog` (`ai`) | < 5% запросов |
| Целостность аудита | `/api/audit/verify` | OK |
