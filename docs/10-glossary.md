# 10. Глоссарий

## Клинические термины

| Термин | Значение в системе |
|---|---|
| **СППВР / CDSS** | Система поддержки принятия врачебных решений: предлагает варианты, решение принимает врач |
| **Кейс** | Клинический случай (`Case`): документы + анализ + отчёты + согласия |
| **ЭМК** | Электронная медицинская карта пациента (`Patient` + визиты/витальные/лаборатория/…) |
| **Рабочий диагноз** | Гипотеза № 1 в диф. ряду с наибольшей вероятностью; не является подтверждённым диагнозом |
| **Гипотеза** | Версия диагноза с аргументами «за/против», вероятностью и планом подтверждения |
| **Красный флаг** | Признак, требующий немедленного изменения тактики (госпитализация, неотложная помощь) |
| **Дифференциальный ряд** | Упорядоченный список 3–5 гипотез, объясняющих клиническую картину |
| **План дообследования** | Исследования, подтверждающие/исключающие гипотезы, с приоритетом, сроком и критериями |
| **Терапия после подтверждения** | Опции лечения, привязанные к гипотезе; заблокированы до подтверждения диагноза |
| **Мониторинг** | Маркеры контроля эффективности/безопасности с целью и частотой |
| **DDI** | Drug–Drug Interaction — лекарственное взаимодействие |
| **КР** | Клинические рекомендации (Минздрав РФ — приоритетный источник) |
| **МКБ-10** | Международная классификация болезней, 10-й пересмотр |
| **ФЗ-152** | Закон РФ «О персональных данных» |
| **PHI** | Protected Health Information — защищаемая медицинская информация |
| **Согласие (`Consent`)** | Документ/запись о согласии пациента на обработку, ИИ-анализ, генетику, передачу отчёта, хранение |

## Технические термины

| Термин | Значение |
|---|---|
| **LLM** | Большая языковая модель (локальный llama-server / LM Studio) |
| **VLM** | Vision-Language Model — анализ изображений (снимков) |
| **Промпт-контракт** | Жёстко заданная структура ответа модели (`### РАЗДЕЛ`, поля, правила) |
| **Самопроверка (verification pass)** | Второй проход модели: аудит черновика и исправления |
| **Структуризация** | Превращение текста заключения в JSON (`extractStructuredJson`) |
| **Нормализация** | Детерминированное исправление формы структуры (ранги, дубли, `targetDx`) |
| **Формальная проверка** | 26 правил полноты/согласованности набора рекомендаций (`clinical-audit.ts`) |
| **Трекер** | Серверный учёт статусов и результатов плана обследования (`workupTracker`) |
| **Подтверждение диагноза** | Действие врача (`confirm_dx`), разблокирующее терапию и пишущееся в аудит |
| **Снапшот версии** | Копия предыдущего результата анализа (`AnalysisVersion`) |
| **RAG** | Retrieval-Augmented Generation — подмешивание найденных источников в контекст |
| **Минздрав RAG** | Прямой разбор репозитория `cr.minzdrav.gov.ru` |
| **Circuit breaker** | Предохранитель внешних вызовов: после серии ошибок хост временно не опрашивается |
| **SSE** | Server-Sent Events — поток событий (используется в DDI) |
| **JWT** | JSON Web Token (HS256, TTL 2 ч) |
| **RBAC** | Ролевой доступ (`admin` / `doctor`) |
| **IDOR** | Insecure Direct Object Reference — доступ к чужому объекту по ID |
| **E2EE** | End-to-End Encryption: ключи у врача, сервер видит шифротекст |
| **DEK / PDEK / KEK** | Ключ врача / ключ пациента / ключ-обёртка, производный от пароля |
| **Argon2id** | KDF для вывода KEK из парольной фразы (128 MiB, 3 итер. по умолчанию) |
| **scrypt** | KDF для файлового шифрования (`ENCRYPTION_KEY`) |
| **AES-256-GCM / GCM-SIV** | Аутентифицированное шифрование файлов / каскада полей |
| **X25519** | Обмен ключами для выдачи доступа к карте |
| **Hash-chain / WORM** | Цепочка SHA-256 в аудите; append-only журнал |
| **Де-идентификация** | Удаление/замена прямых идентификаторов до передачи в ИИ |
| **Seed** | Начальные справочники/демо-данные (`src/lib/seed`) |
| **Standalone** | Режим сборки Next.js (`output: "standalone"`) для запуска одним процессом |
| **Proxy (edge)** | `src/proxy.ts` — проверка JWT, RBAC и rate limit на `/api/*` |
| **Query keys** | Ключи TanStack Query (`["case", id]`, `["analysis", id]`) для инвалидации кэша |

## Сокращения в коде

| Обозначение | Расшифровка |
|---|---|
| `dx` | diagnosis (диагноз/гипотеза) |
| `workup` | план дообследования |
| `confirmedDx` | подтверждённые врачом диагнозы |
| `patientSafety` | снапшот аллергий/терапии/почек для проверки безопасности |
| `normalizationFixes` | автоматические исправления структуры |
| `verification` | отчёт самопроверки ИИ |
| `clinrec` | clinical recommendation (КР) |
| `mkb` | МКБ-10 |
| `ddi` | drug–drug interaction |
| `icd10` | коды МКБ-10 |
| `ner` | named entity recognition |
